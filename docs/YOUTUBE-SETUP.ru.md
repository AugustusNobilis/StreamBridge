# YouTube: настройка StreamBridge

## Ошибка со скриншота: 403 access_denied

Сообщение **«StreamBridge has not completed the Google verification process»** с пояснением про **developer-approved testers** означает, что приложение в режиме Testing, а выбранный аккаунт не допущен.

1. Откройте [Google Cloud](https://console.cloud.google.com/).
2. В верхнем списке выберите **тот проект, которому принадлежит Client ID, вставленный в StreamBridge**.
3. Откройте **Google Auth Platform → Audience / Аудитория → Test users / Тестовые пользователи → Add users**.
4. Добавьте email Google-аккаунта, которым входите, и сохраните.
5. В плагине отмените незавершённый вход, нажмите привязку снова и выберите именно добавленный аккаунт.

Если Client ID получен от другого человека, добавить вас должен владелец его Google Cloud проекта. Изменение списка в другом проекте не поможет. Страница 403 не является предупреждением, которое можно просто пропустить. [Правила режима Testing](https://support.google.com/cloud/answer/15549945).

## 1. Создайте проект и включите API

Откройте [Google Cloud](https://console.cloud.google.com/), выберите или создайте проект для StreamBridge. В **APIs & Services → Library / Библиотека** найдите **YouTube Data API v3** и нажмите **Enable / Включить**. Все следующие настройки делайте в этом же проекте.

## 2. Настройте Google Auth Platform

Откройте **Google Auth Platform**. Если показана кнопка **Get started**, заполните название приложения, почту поддержки и контактную почту. Для обычного личного Google-аккаунта выберите **External / Внешний**.

В **Audience** оставьте **Testing** для личной проверки и добавьте свой аккаунт в **Test users**. Других тестировщиков добавляйте туда же. В **Data Access → Add or remove scopes** добавьте **https://www.googleapis.com/auth/youtube.force-ssl** и сохраните. Это право использует StreamBridge для данных YouTube, чата и управления трансляцией; доступ к Gmail и Drive ему не нужен.

[Настройка экрана согласия Google](https://developers.google.com/workspace/guides/configure-oauth-consent).

## 3. Создайте Client ID

1. В **Google Auth Platform → Clients → Create client** выберите **Desktop app / Приложение для компьютеров**.
2. Назовите клиент, например **StreamBridge Desktop**, и создайте его.
3. Откройте созданный клиент и нажмите **Download JSON / Скачать JSON**. Если клиент уже существует, используйте его, создавать новый проект не требуется.
4. В OBS откройте **Настройки StreamBridge → YouTube → Настройка подключения · Client ID → Импортировать JSON из Google Cloud…** и выберите скачанный файл.
5. Дождитесь сообщения «Данные Desktop-клиента загружены», затем нажмите **Подключить аккаунт YouTube**.

Нужен именно Desktop, не Web application. Для Desktop не добавляйте вручную Redirect URI: плагин открывает временный локальный адрес обратного вызова автоматически. Импорт берёт client_id и client_secret из раздела installed; адреса серверов из файла не используются. После успешного входа данные сохраняются вместе с токенами в хранилище Windows DPAPI. Файл выбирается только локально: не отправляйте его в чат, GitHub или другим людям. Ручной ввод Client ID остаётся доступен, но для клиентов, требующих client_secret, нужен импорт JSON. [Google: приложения для компьютеров](https://developers.google.com/identity/protocols/oauth2/native-app).

## Если после входа появляется «Return to OBS StreamBridge», а в OBS — ошибка

Эта локальная страница означает получение ответа от браузера, а не завершение обмена кода на токены. В версии 0.2.1 и старше плагин не передавал client_secret Desktop-клиента, что могло приводить к ошибке после успешного согласия Google.

Обновитесь до 0.2.2 или новее, импортируйте JSON своего существующего Desktop-клиента по инструкции выше и подключитесь заново. Если ошибка остаётся, ориентируйтесь на сообщение в OBS: invalid_client — проверьте свежий JSON и существование клиента; invalid_grant — повторите вход, не закрывая настройки. Повторно добавлять тестировщика нужно только при отказе на странице Google, а не из-за самой страницы «Return to OBS».

## 4. Привяжите канал

1. Нажмите **Подключить аккаунт YouTube** — откроется браузер.
2. Выберите Google-аккаунт из **Test users** и нужный канал, если Google предлагает выбор.
3. Проверьте название своего приложения и запрашиваемые права, затем подтвердите доступ. Предупреждение о непроверенном приложении допустимо только если вы узнаёте свой проект; при 403 вернитесь к первому разделу.
4. Не закрывайте окно настроек OBS, пока не появится **Аккаунт подключён**: закрытие отменяет незавершённую авторизацию.

В режиме Testing разрешение и refresh token для этих прав истекают через **7 дней** — понадобится повторный вход. Для массового распространения одного Client ID нужны отдельная подготовка приложения и выполнение требований Google.

## 5. Создайте трансляцию и выберите её в плагине

1. Откройте [YouTube Studio](https://studio.youtube.com/), выберите нужный канал и откройте **Создать → Начать трансляцию**.
2. Подготовьте эфир **через видеокодер / Streaming software**, не через веб-камеру. Задайте название, доступ и настройки потока. Если прямые эфиры ещё не разрешены, выполните требования, показанные YouTube.
3. Для запланированного эфира откройте его в диспетчерской и настройте ключ потока. Нужна трансляция с привязанным потоком.
4. В StreamBridge нажмите **Загрузить существующие трансляции**, выберите нужную из списка и **Использовать выбранную трансляцию**.
5. Дождитесь подтверждения сохранения RTMPS-настроек и ключа. Сохраните настройки.
6. Нажмите **Старт** у YouTube в основной панели StreamBridge. Проверьте получение сигнала в Studio; если автоматический старт выключен, запустите эфир также в Studio.

Плагин использует существующий эфир и сам не создаёт, не привязывает и не публикует его через API. Чат, счётчик и редактор работают с выбранной трансляцией. В меню **Док-панели** включите **StreamBridge — Чат**, затем **Подключить чат**.

## Если не получается

| Признак | Что проверить |
| --- | --- |
| 403 с сообщением про тестировщиков | Правильный проект и точный аккаунт в Audience → Test users. |
| redirect_uri_mismatch | Тип клиента **Desktop app**; создайте подходящий клиент вместо Web. |
| invalid_client / ошибка обмена токена | Client ID именно Desktop без лишних символов; не подставляйте API key. Ошибка после согласия может требовать исправления интеграции, а не добавления тестировщика. |
| Список трансляций пуст | Тот ли канал выбран, есть ли незавершённый эфир через видеокодер; нажмите загрузку снова. |
| «Нет привязанного потока» | Откройте этот эфир в Studio и настройте поток/ключ, затем повторите выбор. |
| Ошибка API / квоты | YouTube Data API v3 включён в проекте, аккаунт имеет доступ к каналу, квота не исчерпана. После устранения нажмите обновление; частые повторы не восстанавливают квоту. |
| Чат пуст | Выбран нужный эфир, чат разрешён в Studio, нажато «Подключить чат». |

## Только видео, без Google Cloud

В Studio скопируйте ключ потока. В StreamBridge выберите основной сервер YouTube, вставьте ключ в поле **Ключ трансляции**, нажмите **Сохранить ключ** и сохраните настройки. Запустите вывод и проверьте сигнал в Studio. OAuth не нужен для передачи видео, но одного ключа недостаточно для чата, зрителей и редактора через API.

Не публикуйте ключи потока, токены или загруженный JSON учётных данных. Полная проверка входа с конкретным зарегистрированным Client ID требует реального аккаунта; автоматические тесты проекта её не заменяют.
